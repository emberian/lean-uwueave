Machine-checked answers to a question loom builders keep asking

“Isn’t the hard part of a DAG/tree CRDT just enforcing the requirements of a DAG/tree?” — yes, and a small Lean 4 development can say exactly where that hardness lives, where it vanishes, and what the workarounds provably cost.

uwueave is a companion to universal-weave: it classifies weave/loom invariants by whether they can be replicated with zero coordination, refutes the ones that can’t with concrete two-replica counterexamples, and ships a Rust crate implementing the fragment the theorems bless. No mathlib — lake build finishes in seconds on a laptop.

The three-sentence version

  1. The question is never “is my merge a CRDT”, it is “does my invariant survive my merge.” Bailis et al. proved this test (invariant confluence) is necessary and sufficient: if an invariant fails it, no library, however clever, can maintain it coordination-free — you are choosing among escalation (coordinate), arbitration (someone loses), and compensation (repair after).
  2. Acyclicity fails the test for arbitrary edge insertion (a→b ∪ b→a: two legal DAGs, one merged cycle) but a stronger, edge-local invariant passes it and implies acyclicity — “every edge descends in rank”, which content-addressing gives you for free because a hash-linked node’s parents must exist before the child can be named. Append-only weaves get DAG-ness at any replication scale with no cycle check at all.
  3. The edits that leave that island — move, split, merge-nodes — go through the op-log pattern: replicate the grow-only set of operations, derive the structure by deterministic cycle-skipping replay. Convergence and DAG-ness are then theorems; the honest price (also a theorem) is that an older remote op can retroactively un-apply a move you watched happen.

Sentence two, drawn

The DAG dichotomy

Same goal — a graph that stays acyclic under replication — two ways of inserting edges, opposite verdicts. Both panels below are actual states from the proofs in Uwueave/Acyclicity.lean, not illustrations of a vibe.

def Grounded (rank : Nat → Nat) (g : EdgeGraph) : Prop :=
  ∀ a b : Nat, g (a, b) = true → rank b < rank a

theorem causal_dag_free (rank : Nat → Nat) :
    IConfluent (S := EdgeGraph) (Grounded rank)
    ∧ ∀ g : EdgeGraph, Grounded rank g → Acyclic g

One honest footnote, stated in the source too: “a reference cycle would require a hash cycle” is a cryptographic premise, not a theorem here. The Lean models rank as an explicit function and says so, rather than pretending to have proved anything about SHA-2.

The catalog

Every construction, classified

The whole library is stated against one judgement. An invariant I is I-confluent when every merge of two legal replicas is legal:

def IConfluent {S : Type u} [MergeState S] (I : Invariant S) : Prop :=
  ∀ x y : S, I x → I y → I (x ⊔ y)

Failure is constructive — escalation_witness proves that a non-confluent invariant always yields an actual pair of legal states whose merge is illegal. That pair is the bug report: it is precisely the scenario your users will hit, and it is what a test should replay.

free Proved I-confluent: the merge can never break it. Zero coordination, at any number of replicas.
escalates Refuted with a concrete clashing pair. No library can save it; choose escalation, arbitration, or compensation.
pattern Not free as direct state mutation, but a proved rephrasing (op-log, escrow, segmentation) is — at a proved, named price.

G-Set grow-only set

  • free gset_mem_iconfluent — anything a replica has observed survives every merge: node presence, tombstones, bookmarks, acks. Absence too (gset_notmem_iconfluent), and any monotone-closed invariant (gset_monotone_iconfluent).
  • escalates gset_atMostOne_not_iconfluent — any ceiling on a grow-only structure: {0} and {1} are each singletons; their union is not.
  • escalates or_breaks_iconfluence — mutual exclusion, however phrased: “only Alice holds the lock or only Bob does” is a disjunction of two free invariants, and disjunction does not lift.

Counters G-Counter / PN-Counter

  • free gcounter_lowerBound_iconfluent — grow-only lower bounds survive, because merge only raises counts.
  • escalates pncounter_nonneg_not_iconfluent — Bailis’s motivating example: both replicas legally spend the same 10 credits; the merge has spent 20 against 10. A bounded shared resource cannot be replicated coordination-free.

LWW register last-writer-wins

  • free lww_every_invariant_iconfluent — the join selects one of its arguments, so a single register can never merge-break any invariant (selection_iconfluent).
  • escalates lww_cross_field_not_iconfluent — two registers can: the merged document keeps field A from one replica and field B from the other, an interleaving neither replica ever had. Per-field LWW is safe alone and unsafe relationally.

Escrow the bounded counter, done right

  • free escrow_local_bound_iconfluent — same resource and safety goal as the PN-counter, opposite verdict: the bound is pre-partitioned into per-replica quotas, per-replica invariants are pointwise, and the global bound follows by summing (escrow_global_bound).

OR-Set observed-remove, add-wins

  • escalates orset_present_not_iconfluent — bare presence: each replica keeps the element alive through a tag the other has tombstoned; the merge tombstones both and the element is gone.
  • free orset_present_survives — the correctly scoped guarantee, and what “add-wins” actually means: presence through a tag the other side has not tombstoned survives the merge.

Causal-length set membership as parity

  • free clset_present_iconfluent (and clset_absent_iconfluent) — per-key max selects one side’s count; the arbitration is baked into the counter: the longer history wins the element.
  • escalates clset_cross_element_not_iconfluent — cross-element implications die exactly as LWW pairs did: selection lattices compose into non-selection lattices.

MV-register keep the fork, show the fork

  • pattern The replicated state is a grow-only set of tagged writes; the value is a derived view. What you see is the causal frontier (view_antichain), concurrent writes both surface where LWW would coin-flip (conflict_surfaces), and clearing a conflict is an ordinary write at a dominating clock (resolution_is_a_write) — no special merge case to get wrong. For a loom this is the product, not a consolation prize: a weave wants forks visible.

Vector clocks & fork evidence causality and accountability

  • free vclock_leq_iff — happened-before is exactly the lattice order of the merge, so sync can neither drop nor invent knowledge (and merging genuinely concurrent states makes real progress: concurrent_merge_strict).
  • free fork_evidence_iconfluent — evidence of equivocation is a monotone fact of a grow-only set: once any replica holds a fork proof, no future gossip erases it. And one block frames nobody (no_unilateral_evidence).

Moves as an op-log the Kleppmann move-op shape

  • pattern derived_view_sec — replicate the grow-only op set, derive the tree by timestamp-ordered, cycle-skipping replay: order-independence, redelivery-immunity, and invariant enforcement in one generic statement (the miniature interpreter discharges the enforcement obligation: miniInterp_acyclic).
  • the price view_not_stable — an older remote op can retroactively un-apply a move you watched happen. A theorem, not a bug report. Details below.

Segmented confluence coordination, only at the seams

  • pattern One invariant, both verdicts: a budgeted quota state fails I-confluence outright (budget_not_iconfluent — two legal allocations merge over budget) yet is segmented-confluent over the allocation (budget_segmented). Spends never wait; re-allocation is the named coordination point. Plain I-confluence is exactly the one-segment case (iconfluent_iff_trivially_segmented).

The active path loom-specific: activation / deactivation

  • escalates active_path_not_iconfluent — a shared replicated active path is not a CRDT: two users activate sibling branches, each state is a legal path, and the merged flag-set lights both — no longer a path.
  • free per_user_activation_free — make activation per-user (a keyed map). Also the better UX: “whose cursor wins” is not a question a merge should answer.

Sentence three, priced

Square edits, round holes: the op-log pattern

The dichotomy ends at the island’s shore: append-only, parents-fixed insertion is free, but node moving — which universal-weave’s DAG weave supports, and which every filesystem-shaped application wants — re-points existing edges. Concurrent moves can close a cycle, so a naive “the graph is the CRDT” design is ruled out by necessity, not by lack of cleverness. The pattern that works is:

Replicate the monotone thing. Derive the invariant-bearing thing.

The replicated state is the set of operations ever issued — a grow-only set, trivially a CRDT. The tree the user sees is a pure function of that set: order the ops by timestamp, apply each, skip any whose application would violate the invariant. Convergence is inherited from the log; the invariant holds at every replica by construction of the interpreter. derived_view_sec proves all of this once, generically, for any log-shaped CRDT, any deterministic interpreter, any enforced invariant — and it is one of the two theorems in the library that depend on zero axioms.

The honest price, also a theorem. The derived view is not stable under log growth:

theorem view_not_stable :
    ∃ l l' : GSet MoveOp, LogLe l l'
      ∧ miniInterp l  false = some true
      ∧ miniInterp l' false ≠ some true

Concretely: at t = 2 you move node n₀ under n₁ and watch it happen. A remote op from t = 1 arrives later — older, so it sorts first in replay — moving n₁ under n₀. The replay applies the old op, finds yours cycle-creating, and skips it. The edit the local user watched happen has been un-happened by an op from the past.

The square edit’s nonmonotonicity did not vanish; it moved out of the merge (where it would block convergence) and into the meaning of your local history (where it is an anomaly users can see). That trade is usually right for a loom, and it is still a trade: treat replay output as watchable state, and consider surfacing skipped ops to the user rather than silently dropping their move.

Composition

A fluid, proof-carrying schema DSL

A real document is a record of fields, and the catalog is meant to be composed: a schema is an ordinary Lean type built with × and →, and its classification is a Verdict that carries its own evidence — Verdict.free holds an actual IConfluent proof; Verdict.clash holds a two-replica counterexample that transports up through every combinator. A loom document schema, assembled and classified:

/-- nodes : grow-only id set · meta : per-node LWW · bookmarks : escrowed quota -/
abbrev LoomDoc := GSet Nat × ((Nat → LWW) × Escrow Bool)

def loomInv (quota : Bool → Nat) : Invariant LoomDoc := fun d =>
  (d.1 0 = true)
  ∧ ((∀ k, 1 ≤ (d.2.1 k).ts) ∧ (∀ i, d.2.2 i ≤ quota i))

/-- The whole document replicates coordination-free — one combinator per
schema node. The term *is* the classification report. -/
def loomVerdict (quota : Bool → Nat) : Verdict (loomInv quota) :=
  .free (product_iconfluent
    (gset_mem_iconfluent 0)
    (product_iconfluent
      (pi_iconfluent fun _ => lww_every_invariant_iconfluent (fun r => 1 ≤ r.ts))
      (escrow_local_bound_iconfluent quota)))

Now poison one field. Add an innocent-looking feature — “a document has at most one pinned node”, a uniqueness ceiling on a grow-only set — and the document stops being coordination-free, with the pin-set’s {0}/{1} clash transported to a whole-document repro:

abbrev PinnedDoc := GSet Nat × GSet Nat  -- (nodes, pins)

def pinnedInv : Invariant PinnedDoc := fun d =>
  (d.1 0 = true) ∧ (∀ m n, d.2 m = true → d.2 n = true → m = n)

/-- Two replicas that each pin a different node: both legal whole documents,
their merge pins two. The evidence is a pair of complete document states —
paste them into a test. -/
def pinnedVerdict : Verdict pinnedInv :=
  Verdict.prodClashRight (IA := fun s => s 0 = true)
    (IB := fun s => ∀ m n, s m = true → s n = true → m = n)
    (fun n => n == 0) (fun n => n == 1)
    (fun m n hm hn => by simp at hm hn; omega)
    (fun m n hm hn => by simp at hm hn; omega)
    (fun hmerge => by
      have := hmerge 0 1 (by decide) (by decide)
      omega)
    (fun n => n == 0) (by decide)

example : (loomVerdict (fun _ => 64)).isFree = true  := rfl
example : pinnedVerdict.isFree = false := rfl

Both answers are backed by the terms, not by the Bool. When the DSL hands you a clash, Segmented.lean’s recipe applies: look for a projection your application can hold fixed between explicit coordination events, and check whether the invariant is segmented over it. The clash says coordination is needed somewhere; the segmentation says it is needed only there.

Claim discipline

What is and is not claimed

  • Proved, in Lean, over Lean core only: every MergeState instance’s merge laws (commutative, associative, idempotent — proved, not assumed), every classification above, and every refutation as a concrete two-replica counterexample you can replay as a test.
  • The Lean verifies the design; the Rust is an unverified implementation of it. The companion crate (rust/, one dependency: blake3) implements the blessed fragment — causal::CausalWeave, an append-only content-addressed DAG whose merge is skip-if-present union with no cycle check, the theorems being why that’s sound; and movelog::MoveLog, moves as a grow-only op set with cycle-skipping replay. Its tests replay the Lean witness scenarios — good tests, and zero formal evidence. No “translation validation” is claimed, because there is no formal semantics of Rust to state it in.
  • The content-addressing step is a premise, not a theorem. “A reference cycle would require a hash cycle” is collision resistance — a cryptographic assumption stated out loud. Rank is modeled as an explicit function; nothing is proved about any hash function. Same seam on the implementation side: same-id-different-bytes is refused as corruption (IdCollision), never silently deduped, because the convergence proofs assume ids resolve identically.
  • free means the merge preserves the invariant. It does not mean an operation cannot violate it locally (op-validation is the application’s job), and it does not price metadata growth (tombstones, op logs — engineering, not semantics).
  • The axiom ledger is a build gate, not a printout. Audit.lean pins every keystone theorem’s axiom footprint with #guard_msgs: a sorry (sorryAx) or native_decide (Lean.ofReduceBool) anywhere fails the build. The permitted floor is Lean’s own three axioms — propext, Classical.choice, Quot.sound — and two theorems are pinned axiom-free entirely: grounded_acyclic and derived_view_sec.

Check it yourself:

lake build          # the proofs; Lean core only, no mathlib, ~30s cold
cd rust && cargo test
