Machine-checked answers to a question loom builders keep asking

uwueave classifies the invariants of replicated structures — sets, counters, registers, sequences, maps, permission systems, automata, and the weave/loom documents of universal-weave — by whether they can survive merging with zero coordination: every safe one gets a proof, every impossible one a concrete two-replica counterexample, and every workaround a proved price. The companion Rust crate implements the blessed fragment, and its trickiest decision — the move-replay kernel — is compiled from the Lean itself, not re-implemented.

The three-sentence version

  1. The question is never “is my merge a CRDT”, it is “does my invariant survive my merge.” Bailis et al. proved this test (invariant confluence) is necessary and sufficient: if an invariant fails it, no library, however clever, can maintain it coordination-free — you are choosing among escalation (coordinate), arbitration (someone loses), and compensation (repair after).
  2. Acyclicity fails the test for arbitrary edge insertion (a→b ∪ b→a: two legal DAGs, one merged cycle) but a stronger, edge-local invariant passes it and implies acyclicity — “every edge descends in rank”, which content-addressing gives you for free because a hash-linked node’s parents must exist before the child can be named. Append-only weaves get DAG-ness at any replication scale with no cycle check at all.
  3. The edits that leave that island — move, split, merge-nodes — go through the op-log pattern: replicate the grow-only set of operations, derive the structure by deterministic cycle-skipping replay. Convergence and DAG-ness are then theorems; the honest price (also a theorem) is that an older remote op can retroactively un-apply a move you watched happen.

Sentence two, drawn

The DAG dichotomy

Same goal — a graph that stays acyclic under replication — two ways of inserting edges, opposite verdicts. Both panels below are actual states from the proofs in Uwueave/Acyclicity.lean, not illustrations of a vibe.

def Grounded (rank : Nat → Nat) (g : EdgeGraph) : Prop :=
  ∀ a b : Nat, g (a, b) = true → rank b < rank a

theorem causal_dag_free (rank : Nat → Nat) :
    IConfluent (S := EdgeGraph) (Grounded rank)
    ∧ ∀ g : EdgeGraph, Grounded rank g → Acyclic g

One honest footnote, stated in the source too: “a reference cycle would require a hash cycle” is a cryptographic premise, not a theorem here. The Lean models rank as an explicit function and says so, rather than pretending to have proved anything about SHA-2.

The catalog

Every construction, classified

The whole library is stated against one judgement. An invariant I is I-confluent when every merge of two legal replicas is legal:

def IConfluent {S : Type u} [MergeState S] (I : Invariant S) : Prop :=
  ∀ x y : S, I x → I y → I (x ⊔ y)

Failure is constructive — escalation_witness proves that a non-confluent invariant always yields an actual pair of legal states whose merge is illegal. That pair is the bug report: it is precisely the scenario your users will hit, and it is what a test should replay.

free Proved I-confluent: the merge can never break it. Zero coordination, at any number of replicas.
escalates Refuted with a concrete clashing pair. No library can save it; choose escalation, arbitration, or compensation.
pattern Not free as direct state mutation, but a proved rephrasing (op-log, escrow, derived view) is — at a proved, named price.
seam Not free globally, free within the fibers of a projection: coordinate only when the seam moves.

G-Set grow-only set

  • free gset_mem_iconfluent — anything a replica has observed survives every merge: node presence, tombstones, bookmarks, acks. Absence too (gset_notmem_iconfluent), and any monotone-closed invariant (gset_monotone_iconfluent).
  • escalates gset_atMostOne_not_iconfluent — any ceiling on a grow-only structure: {0} and {1} are each singletons; their union is not.
  • escalates or_breaks_iconfluence — mutual exclusion, however phrased: “only Alice holds the lock or only Bob does” is a disjunction of two free invariants, and disjunction does not lift.

Counters G-Counter / PN-Counter

  • free gcounter_lowerBound_iconfluent — grow-only lower bounds survive, because merge only raises counts.
  • escalates pncounter_nonneg_not_iconfluent — Bailis’s motivating example: both replicas legally spend the same 10 credits; the merge has spent 20 against 10. A bounded shared resource cannot be replicated coordination-free.

LWW register last-writer-wins

  • free lww_every_invariant_iconfluent — the join selects one of its arguments, so a single register can never merge-break any invariant (selection_iconfluent).
  • escalates lww_cross_field_not_iconfluent — two registers can: the merged document keeps field A from one replica and field B from the other, an interleaving neither replica ever had. Per-field LWW is safe alone and unsafe relationally.

Escrow the bounded counter, done right

  • free escrow_local_bound_iconfluent — same resource and safety goal as the PN-counter, opposite verdict: the bound is pre-partitioned into per-replica quotas, per-replica invariants are pointwise, and the global bound follows by summing (escrow_global_bound).

OR-Set observed-remove, add-wins

  • escalates orset_present_not_iconfluent — bare presence: each replica keeps the element alive through a tag the other has tombstoned; the merge tombstones both and the element is gone.
  • free orset_present_survives — the correctly scoped guarantee, and what “add-wins” actually means: presence through a tag the other side has not tombstoned survives the merge.

Causal-length set membership as parity

  • free clset_present_iconfluent (and clset_absent_iconfluent) — per-key max selects one side’s count; the arbitration is baked into the counter: the longer history wins the element.
  • escalates clset_cross_element_not_iconfluent — cross-element implications die exactly as LWW pairs did: selection lattices compose into non-selection lattices.

OR-Map documents are maps; maps are the hard part

  • free ormap_get_survives — add-wins at map level, correctly scoped and with the value included: a key alive through a tag the other side has not tombstoned stays present and readable. Key presence is the OR-Set (present_iff_orset is Iff.rfl), so ormap_present_not_iconfluent is inherited by projection, not re-proved.
  • escalates ormap_doomed_update — the map-specific anomaly, reachable even under causal delivery: a nested write concurrent with its key’s removal survives the merge but is masked by the view — doomed, not dropped.
  • the fork ormap_policy_divergence — the centerpiece: on one merged state, the remove-wins view shows ⟨1,10⟩ and refuses ⟨2,99⟩ while the resurrect view shows ⟨2,99⟩ and refuses ⟨1,10⟩. The merge is policy-neutral; the choice lives in the view, and each policy is the other’s anomaly. ormap_policies_agree_without_removes confines the fork to removal-touched keys.

MV-register keep the fork, show the fork

  • pattern The replicated state is a grow-only set of tagged writes; the value is a derived view. What you see is the causal frontier (view_antichain), concurrent writes both surface where LWW would coin-flip (conflict_surfaces), and clearing a conflict is an ordinary write at a dominating clock (resolution_is_a_write) — no special merge case to get wrong. For a loom this is the product, not a consolation prize: a weave wants forks visible.

Undo / redo multi-user, on the MV-register

  • pattern The Stewen–Kleppmann (PaPoC 2024) insight in miniature: an undo is an ordinary write at a fresh clock, so no new operation ever reaches the merge. The view restores exactly (undo_restores, redo_restores — stated as view characterizations, so “only” is proved), and history is never rewritten (undo_preserves_history).
  • free undo_conflicts_visibly / undo_does_not_silently_lose — the multiplayer punchline: an undo racing a concurrent edit is just two concurrent writes, so both surface as an MV conflict. Nobody’s edit dies silently.

Vector clocks & fork evidence causality and accountability

  • free vclock_leq_iff — happened-before is exactly the lattice order of the merge, so sync can neither drop nor invent knowledge (and merging genuinely concurrent states makes real progress: concurrent_merge_strict).
  • free fork_evidence_iconfluent — evidence of equivocation is a monotone fact of a grow-only set: once any replica holds a fork proof, no future gossip erases it. And one block frames nobody (no_unilateral_evidence).

Delta shipping the join cannot tell how the news arrived

  • free The delta-CRDT receiver is one fold of ⊔ (joinAll), and the merge laws make delivery histories indistinguishable: order (joinAll_perm), duplication (joinAll_dup, joinAll_redeliver), batching (joinAll_batch, joinAll_append_merge). The composite, same_deltas_same_state: same delta-set, any order, any duplication, any batching — same replica. Twelve of the file’s sixteen theorems are pinned axiom-free.
  • free addDelta_least — the G-Set add-delta is the least lattice element that delivers its element: the minimal patch and the full state meet the same join.

Moves as an op-log the Kleppmann move-op shape

  • pattern derived_view_sec — replicate the grow-only op set, derive the tree by timestamp-ordered, cycle-skipping replay: order-independence, redelivery-immunity, and invariant enforcement in one generic statement (the miniature interpreter discharges the enforcement obligation: miniInterp_acyclic).
  • the price view_not_stable — an older remote op can retroactively un-apply a move you watched happen. A theorem, not a bug report. Details below — and the kernel section takes this pattern all the way to compiled code.

Anchored sequences RGA-style text, anomaly included

  • free wf_iconfluent — anchored insertion needs no coordination, and the visible text is a derived view (sequence_view_sec): every present element appears (linearize_mem), its anchor somewhere before it (linearize_anchor_precedes). Exactly-once (linearize_count_one) needs an id-uniqueness premise — and wf_unique_anchor_not_iconfluent proves that premise is not free; content-addressing discharges it cryptographically.
  • the anomaly interleaving_anomaly — two contiguous two-element runs merge to [4, 3, 2, 1], strictly alternated; run_order_by_id shows merged order is id arbitration, not intention. No-interleaving is explicitly not claimed — that is what real sequence CRDTs (Loro, Fugue) are for.

Replicated automata state machines under sync

  • free run_same_inputs — semilattice-action runs (the CALM / LVars class) converge as one-line instances of the delta laws. And with no lattice at all, pairwise commutation already suffices: exec_perm (pinned axiom-free) is the commuting-batch replay theorem — the seed of the Mazurkiewicz/Zielonka connection, cited, not claimed.
  • escalates determinism_not_iconfluent — the machine itself as replicated data: enabledness grows, determinism dies. DFA determinism is a uniqueness ceiling on a grow-only transition table; the priced exits are LWW-arbitrating the slot or accepting the NFA as the visible conflict surface.
  • seam token_firings_segmented — escrowed token firing reads the segmented budget as a Petri net: firing = local spend, free within an allocation (concurrent_firings_merge_legal); moving tokens between pools is the coordination seam (token_reallocation_not_iconfluent).

Authority local-first permissions, fail-closed

  • free wf_iconfluent — delegation is coordination-free: attenuated grants can be issued offline, in a partition, on a plane, and every merge is again a well-formed grant DAG. Authority provably only narrows (chain_scope_descends, scope_le_root, packaged as authority_only_narrows): nobody manufactures scope, under any merge schedule.
  • free authority_view_antitone — revocation is fail-closed: growing the revocation set never increases anyone’s derived authority; late revocations only shrink it (revocation_is_forever). This is the security dual of view_not_stable — the same lattice instability, pointed in the safe direction.
  • escalates sole_admin_not_iconfluent and duelling_revocations_not_iconfluent — “one admin” is mutual exclusion in authority clothes, and concurrent revocations annihilate both duellists (duelling_admins_annihilate). Keeping a survivor costs exactly the arbitration ERA introduces — cited, priced, not hidden.

Segmented confluence coordination, only at the seams

  • seam One invariant, both verdicts: a budgeted quota state fails I-confluence outright (budget_not_iconfluent — two legal allocations merge over budget) yet is segmented-confluent over the allocation (budget_segmented). Spends never wait; re-allocation is the named coordination point. Plain I-confluence is exactly the one-segment case (iconfluent_iff_trivially_segmented), and the DSL carries this verdict first-class — SegVerdict, below.

The active path loom-specific: activation / deactivation

  • escalates active_path_not_iconfluent — a shared replicated active path is not a CRDT: two users activate sibling branches, each state is a legal path, and the merged flag-set lights both — no longer a path.
  • free per_user_activation_free — make activation per-user (a keyed map). Also the better UX: “whose cursor wins” is not a question a merge should answer.

Sentence three, priced

Square edits, round holes: the op-log pattern

The dichotomy ends at the island’s shore: append-only, parents-fixed insertion is free, but node moving — which universal-weave’s DAG weave supports, and which every filesystem-shaped application wants — re-points existing edges. Concurrent moves can close a cycle, so a naive “the graph is the CRDT” design is ruled out by necessity, not by lack of cleverness. The pattern that works is:

Replicate the monotone thing. Derive the invariant-bearing thing.

The replicated state is the set of operations ever issued — a grow-only set, trivially a CRDT. The tree the user sees is a pure function of that set: order the ops by timestamp, apply each, skip any whose application would violate the invariant. Convergence is inherited from the log; the invariant holds at every replica by construction of the interpreter. derived_view_sec proves all of this once, generically, for any log-shaped CRDT, any deterministic interpreter, any enforced invariant — and it is pinned to depend on zero axioms.

The honest price, also a theorem. The derived view is not stable under log growth:

theorem view_not_stable :
    ∃ l l' : GSet MoveOp, LogLe l l'
      ∧ miniInterp l  false = some true
      ∧ miniInterp l' false ≠ some true

Concretely: at t = 2 you move node n₀ under n₁ and watch it happen. A remote op from t = 1 arrives later — older, so it sorts first in replay — moving n₁ under n₀. The replay applies the old op, finds yours cycle-creating, and skips it. The edit the local user watched happen has been un-happened by an op from the past.

The square edit’s nonmonotonicity did not vanish; it moved out of the merge (where it would block convergence) and into the meaning of your local history (where it is an anomaly users can see). That trade is usually right for a loom, and it is still a trade: treat replay output as watchable state, and consider surfacing skipped ops to the user rather than silently dropping their move.

The implementation, without a twin

The Lean-compiled kernel

The op-log pattern’s delicate part is the replay: the total order, the cycle rule, the skip. In most “verified design” projects that logic gets re-implemented in the production language, and the proofs and the code start drifting the day the re-implementation lands. Here it does not, because there is no second copy of the rules: the replay decision procedure is authored in Uwueave/Exec.lean, exported with @[export uwueave_replay_kernel], compiled to C by lake alongside every other module, and linked into the Rust crate by build.rs. The Rust movelog module marshals bytes; it contains no replay implementation to drift.

Inside the Lean, the kernel is factored so the byte layer needs no theorem at all — replay is literally a composition, not a re-implementation, so there is no fold-vs-bytes agreement left to prove. The decision layer is the named function absReplay:

/-- The replay: literally decode → absReplay → encode. -/
def replay (input : ByteArray) : ByteArray :=
  encodeView (absReplay (decodeBase input) (decodeOps input))

@[export uwueave_replay_kernel]
def replayKernel (input : ByteArray) : ByteArray :=
  replay input

And Uwueave/ExecRefine.lean proves the facts about that layer that are not free (axioms within Lean’s own three; no sorry, no native_decide, no #guard):

  • absReplay_acyclic — the general acyclicity theorem: on a grounded base (some rank strictly descends along the structural first parents — the shape content-addressing provides), replaying any op array — order, duplication and content unconstrained, junk indices included — yields an effective-parent relation with no cycle. miniInterp_acyclic, generalized from the two-op miniature to the real kernel, for all inputs. With absReplay_terminates and absReplay_chain_nodup: every override chain reaches root without revisiting a node. 
    theorem absReplay_acyclic (fp : Array Int) (ops : Array Op)
    (r : Nat → Nat) (hg : GroundedBase r fp) :
    ∀ i, ¬ Reaches fp (absReplay fp ops) i i
  • chainHits_decides — fuel adequacy: on the terminating views the kernel maintains, the literal fuel n + 1 decides ancestor-chain membership — a from-scratch pigeonhole argument, so exhaustion never masquerades as “misses” and the cycle-skip check means what it says.
  • decode_encode_id (with getWord_pushWord, size_encodeView, toI_ofI) — the output codec round-trips at the word level: word i of the encoded view decodes back to entry i, and pushed words never disturb earlier ones.

Still open, and said so in the kernel’s own header — three seams, none hidden:

  • The Prop-level Move.lean connection. That this replay is the abstract derived view of the grow-only log is not yet machine-checked — SEC for the real kernel is still inherited informally from the log argument, not by theorem.
  • The input-side codec. decodeBase/decodeOps have no in-kernel encoder to round-trip against; the Rust request encoder is unverified by construction. (Malformed input degrades to junk output, never to unsoundness or a crash — the decoders are total.)
  • The C backend. The kernel is executable Lean compiled by Lean’s verified-nothing C backend and trusted like any compiler output — alongside the 49-line shim and the Rust glue.

Composition

A fluid, proof-carrying schema DSL

A real document is a record of fields, and the catalog is meant to be composed: a schema is an ordinary Lean type built with × and →, and its classification carries its own evidence. The DSL now has three answers, not two: Verdict.free holds an actual IConfluent proof; Verdict.clash holds a two-replica counterexample that transports up through every combinator — through products (prodClashLeft/prodClashRight) and through keyed maps (keyedClash: one clashing key sinks the whole map, with a repro differing from a legal map at exactly that key); and SegVerdict is the refined third answer for when “go to consensus” is too blunt. A loom document schema, assembled and classified:

/-- nodes : grow-only id set · meta : per-node LWW · bookmarks : escrowed quota -/
abbrev LoomDoc := GSet Nat × ((Nat → LWW) × Escrow Bool)

def loomInv (quota : Bool → Nat) : Invariant LoomDoc := fun d =>
  (d.1 0 = true)
  ∧ ((∀ k, 1 ≤ (d.2.1 k).ts) ∧ (∀ i, d.2.2 i ≤ quota i))

/-- The whole document replicates coordination-free — one combinator per
schema node. The term *is* the classification report. -/
def loomVerdict (quota : Bool → Nat) : Verdict (loomInv quota) :=
  .free (product_iconfluent
    (gset_mem_iconfluent 0)
    (product_iconfluent
      (pi_iconfluent fun _ => lww_every_invariant_iconfluent (fun r => 1 ≤ r.ts))
      (escrow_local_bound_iconfluent quota)))

Now poison one field. Add an innocent-looking feature — “a document has at most one pinned node”, a uniqueness ceiling on a grow-only set — and the document stops being coordination-free, with the pin-set’s {0}/{1} clash transported to a whole-document repro:

abbrev PinnedDoc := GSet Nat × GSet Nat  -- (nodes, pins)

def pinnedInv : Invariant PinnedDoc := fun d =>
  (d.1 0 = true) ∧ (∀ m n, d.2 m = true → d.2 n = true → m = n)

/-- Two replicas that each pin a different node: both legal whole documents,
their merge pins two. The evidence is a pair of complete document states —
paste them into a test. -/
def pinnedVerdict : Verdict pinnedInv :=
  Verdict.prodClashRight (IA := fun s => s 0 = true)
    (IB := fun s => ∀ m n, s m = true → s n = true → m = n)
    (fun n => n == 0) (fun n => n == 1)
    (fun m n hm hn => by simp at hm hn; omega)
    (fun m n hm hn => by simp at hm hn; omega)
    (fun hmerge => by
      have := hmerge 0 1 (by decide) (by decide)
      omega)
    (fun n => n == 0) (by decide)

The third answer is the one a schema author actually wants when a clash alone would send every write to consensus. A SegVerdict carries both halves of the refined judgement: the global clash (so free-running is refuted, with a repro — escalatesGlobally), and a seam — a projection σ with a SegmentedIConfluent proof that same-seam merges preserve the invariant and stay in the fiber (freeWithinSeam, staysInSeam — the closure half is load-bearing: a sync can never re-allocate behind your back). The worked instance packages Segmented.lean’s punchline pair as one value:

def budgetSegVerdict : SegVerdict (BudgetInv 10) (Bool → Nat) where
  σ := Prod.fst
  seamFree := budget_segmented 10
  x := ((fun b => if b then 10 else 0), (fun b => if b then 10 else 0))
  y := ((fun b => if b then 0 else 10), (fun b => if b then 0 else 10))
  hx := by refine ⟨⟨?_, ?_⟩, ?_⟩ <;> decide
  hy := by refine ⟨⟨?_, ?_⟩, ?_⟩ <;> decide
  hbad := fun hgood => by
    have := hgood.2
    revert this
    show ¬ (Nat.max 10 0 + Nat.max 0 10 = 10)
    decide

All three verdict kinds, evaluated side by side — and each answer is backed by the terms, not by the Bool:

example : (loomVerdict (fun _ => 64)).isFree = true  := rfl
example : pinnedVerdict.isFree = false := rfl
example : pinnedPerNodeVerdict.isFree = false := rfl   -- keyedClash: one key sinks the map

example : ¬ IConfluent (BudgetInv 10) := budgetSegVerdict.escalatesGlobally

example (a b : QuotaState) (hσ : a.1 = b.1)
    (ha : BudgetInv 10 a) (hb : BudgetInv 10 b) : BudgetInv 10 (a ⊔ b) :=
  budgetSegVerdict.freeWithinSeam hσ ha hb

Reading: spends never coordinate; re-allocation is the only coordination point. The clash says coordination is needed somewhere; the segmentation says it is needed only there. And for a consumer that only understands the binary judgement, every SegVerdict demotes honestly to its clash (toClash).

For the reader with a schema and no interest in proofs

uwueave-check

The repo ships a small command-line tool that answers the library’s question for your fields. Describe your app’s shared state — shapes and the invariants you care about — and every verdict comes back as a citation into a machine-checked theorem: FREE, ESCALATES (with the two-replica repro retold and the exits priced), SEAM, PATTERN — or UNCLASSIFIED, honestly, where no theorem covers the pair. It never guesses.

field pins: gset

Claim discipline

What is and is not claimed

  • Proved, in Lean, over Lean core only: every MergeState instance’s merge laws (commutative, associative, idempotent — proved, not assumed), every classification above, and every refutation as a concrete two-replica counterexample you can replay as a test.
  • Bailis necessity is cited, not re-proved. Theorem 3.1 of the paper — I-confluence is necessary and sufficient for a coordination-free convergent implementation to exist — quantifies over systems and lives in the paper, not in this Lean. So the library uses IConfluent directly and cites the equivalence, rather than defining a synonym that would let rw manufacture a false sense of necessity. What a ¬ IConfluent result here formally provides is the clash witness; the modal reading (“no implementation can…”) is Bailis, cited.
  • The Lean verifies the design — and authors the kernel’s semantics. The companion crate (rust/, one dependency: blake3) implements the blessed fragment: causal::CausalWeave, an append-only content-addressed DAG whose merge is skip-if-present union with no cycle check, the theorems being why that’s sound; and movelog::MoveLog, whose replay is the compiled Lean kernel — no Rust twin exists to drift. What remains unverified: the crate’s storage/index/codec glue, the C shim, Lean’s C backend, and the kernel-to-Move.lean refinement (named open work, above). The tests replay the Lean witness scenarios through the real kernel — good tests, and zero formal evidence. No “translation validation” is claimed, because there is no formal semantics of Rust to state it in.
  • The content-addressing step is a premise, not a theorem. “A reference cycle would require a hash cycle” is collision resistance — a cryptographic assumption stated out loud. Rank is modeled as an explicit function; nothing is proved about any hash function. The same discipline recurs wherever ids do load-bearing work: exactly-once linearization (UniqueAnchor) and grant-chain narrowing (UniqueGrant) are stated as hypotheses the lattice provably does not preserve, discharged cryptographically in a deployment. And on the implementation side, same-id-different-bytes is refused as corruption (MergeError::IdCollision), never silently deduped, because the convergence proofs assume ids resolve identically.
  • free means the merge preserves the invariant. It does not mean an operation cannot violate it locally (op-validation is the application’s job), and it does not price metadata growth (tombstones, op logs — engineering, not semantics).
  • The axiom ledger is a build gate, not a printout. Audit.lean pins all 113 keystone theorems’ axiom footprints with #guard_msgs: a sorry (sorryAx) or native_decide (Lean.ofReduceBool) anywhere fails the build. The permitted floor is Lean’s own three axioms — propext, Classical.choice, Quot.sound — and 32 keystones are pinned to depend on no axioms at all, grounded_acyclic, derived_view_sec, same_deltas_same_state and exec_perm among them. Both counts are grep-checkable against the ledger itself rather than trusted to prose.

Check it yourself:

lake build              # the proofs; Lean core only, no mathlib, ~30s cold
cd rust && cargo test   # compiles the Lean kernel to C and links it (needs elan)
